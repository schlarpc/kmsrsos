slmgr /ato</code></pre><p>For Office, run the same two steps against <code>ospp.vbs</code> in the Office installation directory:</p><pre><code>cscript ospp.vbs /sethst:kms.example.net
cscript ospp.vbs /act</code></pre><p>A client must already be installed with the generic volume licence key for its edition, or it will not contact a KMS host at all. <a href="/products">The product list</a> has them.</p><h2>Or by DNS, so no client needs configuring</h2><p>A client with no explicit host looks up <code>_vlmcs._tcp</code> in the domains it searches, which is how a real KMS deployment is found. Publish one of these; all three say the same thing.</p><h3>BIND-style zone file</h3><pre><code>_vlmcs._tcp  IN  SRV  0 0 1688  kms.example.net.</code></pre><p>The four numbers are priority, weight, port and target. Clients order by ascending priority, then by weighted random choice within a priority (RFC 2782), so a single host needs neither and zero for both is the convention.</p><h3>nsupdate</h3><pre><code>nsupdate &lt;&lt;'EOF'
update add _vlmcs._tcp.EXAMPLE.COM. 3600 SRV 0 0 1688 kms.example.net.
send
EOF</code></pre><h3>Windows DNS, in an Active Directory domain</h3><pre><code>dnscmd . /RecordAdd EXAMPLE.COM _vlmcs._tcp SRV 0 0 1688 kms.example.net</code></pre><p>or the PowerShell equivalent:</p><pre><code>Add-DnsServerResourceRecord -ZoneName EXAMPLE.COM ``
&nbsp; -Name _vlmcs._tcp -Srv -Priority 0 -Weight 0 ``
&nbsp; -Port 1688 -DomainName kms.example.net</code></pre><p>Replace <code>EXAMPLE.COM</code> with the domain the clients search — their primary DNS suffix, which in a domain is the domain itself.</p><h2>Checking it</h2><pre><code>nslookup -type=srv _vlmcs._tcp.EXAMPLE.COM
slmgr /dlv</code></pre><p><code>/dlv</code> prints the host it used and the activation interval, which is the quickest way to tell &lsquo;the client never found a host&rsquo; from &lsquo;the client found one and did not like the answer&rsquo;.</p></body></html>
